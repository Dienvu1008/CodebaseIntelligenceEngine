# Living Documentation Model

> Status: Baseline v0.1 · Related: ADR-0007, ADR-0014, DOC-* and PV-005 invariants, [KNOWLEDGE_GRAPH_DESIGN](KNOWLEDGE_GRAPH_DESIGN.md)

## 1. Principles

1. **Markdown first.** Pages are plain CommonMark with YAML front matter. They are readable on GitHub without CIE.
2. **Ownership is in the file**, through markers (DOC-001). Location does not determine ownership.
3. **Generators splice, never rewrite.** They replace only their own sections, guarded by a hash check (DOC-002/003).
4. **Everything links by stable ID**, never by line number.
5. **Staleness is visible**, never silently "fixed".

## 2. Page locations and kinds

| Location | Contents | Committed |
|---|---|---|
| `wiki.dir` (default `docs/wiki/`) | Curated pages; published generated pages | yes |
| `.cie/wiki/` | Generated drafts (one per concept, module and component) | no |
| `.cie/conflicts/<pageId>/<sectionId>.md` | Proposals blocked by DOC-002 | no |

| Page kind (`cie.kind`) | Typical subject | Generated by default (template, no LLM) |
|---|---|---|
| `concept` | A domain or technical concept | Code locations table, related symbols, mentions |
| `module` | A file or module | Symbol inventory, imports/importers, exports |
| `component` | An architecture component | Dependency table, violations, member packages |
| `flow` | An execution flow | Step list with statuses |
| `guide` | Free-form, user-only | Nothing |
| `index` | Generated listings | Everything |

## 3. Page identity and front matter

```yaml
---
cie:
  id: concepts/session-refresh            # required, workspace-unique, stable (DOC-005)
  kind: concept
  title: Session refresh
  aliases: [token refresh, re-auth]
  subjects:                               # what the page describes (→ describes, user_asserted)
    - concept:session-refresh
  relations:                              # user-authored relations (→ user_asserted claims, PV-005)
    - { type: implements_concept, from: "ts:src/auth/session.ts#SessionStore.refresh(method)" }
    - { type: related_to, to: concept:token-storage }
  abstract: false                         # DOC-008
  generated:                              # owned by the generator (the only generator-owned part of front matter)
    schema: 1
    lastSeq: 42
---
```

- The `id` is independent of the filename. Moving the file keeps the ID.
- Duplicate IDs invalidate both pages until resolved (DOC-005).
- Missing `cie.id` means the page is treated as **unmanaged**: it is indexed for links and search, but generators never write to it. `cie wiki adopt <file>` adds an ID, and only on the user's explicit command.

## 4. Sections and ownership markers

```markdown
<!-- cie:begin section=code-locations gen=template seq=42 hash=sha256:4be1… sources=ts:src/auth/session.ts#SessionStore.refresh(method),ts:src/auth/token-client.ts#TokenClient.fetchToken(method) -->
…generated content…
<!-- cie:end section=code-locations -->
```

| Attribute | Meaning |
|---|---|
| `section` | Section ID, unique per page |
| `gen` | `template` or `llm:<model>` |
| `seq` | Revision the content was generated from (DOC-006) |
| `hash` | SHA-256 of the exact bytes between the markers at the last generator write (DOC-002) |
| `sources` | Symbol, claim and node IDs used. Overflow goes to `state.db` (`sources=@ref:<id>`) when the list is long. |

**Rules:**
- Markers must be paired, non-nested and unique per page. Otherwise the page is `MALFORMED_MARKERS` and receives no writes (DOC-007).
- Everything outside markers is user-owned.

## 5. Write protocol (generator)

```
for each target section S on page P:
  read P (bytes), parse → markers
  if malformed → report, stop (DOC-007)
  if S missing:
     if P is generated-draft (.cie/wiki) → append S
     else if publish policy allows insertion → insert S at the declared anchor
          (`<!-- cie:slot section=... -->`, user-placed) else → skip
  current = bytes between markers of S
  if sha256(current) ≠ S.hash → CONFLICT (write proposal to .cie/conflicts, record) (DOC-002)
  else splice new content, update hash/seq/sources attributes only inside S's begin marker,
       write via temp file + atomic rename under a lock (DOC-003)
       record SectionWrite in state.db (DocumentationRevision log)
```

The insertion slot (`<!-- cie:slot … -->`) means a generator can only *add* sections to a curated page where the user has invited it.

## 6. Links and symbol references

| Syntax | Example | Notes |
|---|---|---|
| Standard Markdown with the `cie:` scheme (**canonical**) | `[SessionStore.refresh](cie:symbol/ts:src/auth/session.ts%23SessionStore.refresh(method))` | Renders anywhere. On GitHub it degrades to a non-navigable link. |
| Concept link | `[Session refresh](cie:concept/session-refresh)` | |
| Page link | `[guide](cie:page/guides/onboarding)` or a relative `.md` link | Relative links to other wiki files are resolved too |
| Wiki-link shorthand (accepted, never rewritten) | `[[concept:session-refresh]]`, `[[ts:src/auth/session.ts#SessionStore.refresh(method)\|refresh]]` | The renderer supports it. CIE never normalizes user text. |
| File link | `[session.ts](cie:file/src/auth/session.ts#L18)` | The line fragment is a *hint*. Resolution uses the file plus an anchor search if a symbol is given. |

**Link states** (DOC-004, computed per revision by `LinkResolver`):

| State | Condition | UI |
|---|---|---|
| `resolved` | Target exists at head | normal |
| `redirected` | Target ID gone, lineage gives a new ID | link works; "moved/renamed" badge; `wiki.validate` suggests an update |
| `stale` | Target exists but changed since the page or section seq (spanHash differs) | link works; "changed since documented" badge |
| `broken` | Target deleted (lineage `deleted`) or never existed | strike-through; reported |

## 7. Staleness detection

- **Section-level** (DOC-006): a generated section is stale when any of its `sources` was modified, moved or deleted, or became stale, after `seq`.
- **Page-level, user content:** CIE cannot know whether prose is still true. It reports **"documented code changed"** when any `cie:` link target in user-owned regions changed after the page's last git commit time or `generated.lastSeq`, whichever is later. This is a signal, not a verdict.
- Stale sections are regenerated only on request (`docs.generate`), or automatically for `.cie/wiki` drafts when `docs.autoRegenerateDrafts` is set. Committed pages are never auto-written unless publish mode is enabled **and** the hash guard passes.

## 8. Conflict resolution

| User action | Effect |
|---|---|
| **Accept proposal** | The proposal replaces the section (hash re-adopted). This is the only path that overwrites edited generated content, and it is always an explicit user action. |
| **Keep mine and re-adopt** | Current content becomes the new baseline hash. The section stays generator-owned. |
| **Detach** | Markers are removed, and the content becomes user-owned permanently. |
| **Ignore** | The conflict persists and is shown in the sync status. |

## 9. Storage of documentation metadata (`index.db`, revision-scoped)

```sql
-- Pages are also nodes (kind 'page'), so they reuse node_key for stable identity (KNOWLEDGE_GRAPH_DESIGN §5).
CREATE TABLE page (rowid INTEGER PRIMARY KEY, page_key INTEGER NOT NULL REFERENCES node_key(key), path TEXT NOT NULL,
  kind TEXT, title TEXT, managed INTEGER NOT NULL, content_hash TEXT NOT NULL,
  valid_from_seq INTEGER NOT NULL, valid_to_seq INTEGER);
CREATE TABLE section (rowid INTEGER PRIMARY KEY, page_key INTEGER NOT NULL REFERENCES node_key(key),
  section_id TEXT NOT NULL, owner TEXT NOT NULL, gen TEXT, gen_seq INTEGER, written_hash TEXT,
  start_offset INTEGER NOT NULL, end_offset INTEGER NOT NULL, freshness TEXT NOT NULL,
  valid_from_seq INTEGER NOT NULL, valid_to_seq INTEGER);
CREATE TABLE link (rowid INTEGER PRIMARY KEY, page_key INTEGER NOT NULL REFERENCES node_key(key),
  section_id TEXT, target TEXT NOT NULL, target_key INTEGER REFERENCES node_key(key),
  state TEXT NOT NULL, start_offset INTEGER NOT NULL, valid_from_seq INTEGER NOT NULL, valid_to_seq INTEGER);
```

`state.db` holds the `section_write` log (DocumentationRevision), `conflict` records and the LLM response cache.

## 11. Example source-reference mapping and drift scenarios

Anchor recorded at seq 42:

```json
{ "symbolId": "ts:src/auth/session.ts#SessionStore.refresh(method)",
  "path": "src/auth/session.ts", "range": { "startLine": 17, "startCol": 2, "endLine": 31, "endCol": 3 },
  "spanHash": "sha256:5c1e…", "seq": 42 }
```

| Scenario (head = 47) | Index state at 47 | `AnchorResolver` result | Navigation | Link state |
|---|---|---|---|---|
| **A. Edit above the symbol** (10 lines inserted at the top of the file) | Same ID; range now 27–41; spanHash unchanged | `resolved` (location updated) | Reveals line 27 | resolved |
| **B. Body edit** | Same ID; spanHash changed | `resolved` + `changed` | Reveals the new range, with a "changed since documented" note | stale |
| **C. Rename to `renewSession`** | Old ID missing; new ID `…#SessionStore.renewSession(method)` with an equal bodyFingerprint; lineage `renamed@45` | `redirected` → new ID | Reveals `renewSession` | redirected (validate suggests an update) |
| **D. Move to `src/auth/refresh.ts`** | Lineage `moved@46`: old → `ts:src/auth/refresh.ts#SessionStore.refresh(method)` | `redirected` | Opens the new file at the symbol | redirected |
| **E. Rename and body edit in the same change** | No fingerprint match → lineage `deleted@47`; a new symbol appears | `deleted` (last known location shown) | Offers candidates: same container plus a similar name (by edit distance), labeled *suggestions*, never auto-followed | broken |
| **F. Unsaved edit in the editor** (index at 47 unaware) | — | The index says 27–41. The extension cross-checks the live document symbols (VSCODE_EXTENSION_DESIGN §6). | Reveals the live position of `refresh` in the buffer | n/a |
| **G. File deleted** | File and symbol closed; lineage `deleted@47` | `deleted` | Shows a "removed in revision 47" notice | broken |

Scenario E is the honest limitation: when identity evidence is lost, CIE reports `deleted` and offers labeled suggestions rather than guessing.
